# たまご日和 — ゲーム・UI/UX仕様

制作基準日：2026-09-27 / バージョン：設計1.0 / 仮タイトル

## 1. 体験の核

「じゅわっ、とろっ。今日のひと皿。」

目の前の卵が目玉焼きになる小さな気持ちよさを、タップ中心で楽しむ。料理の正解を一つにせず、選んだ焼き加減へ近づける遊びとする。短い1プレイ、見た目から分かる変化、結果に応じた一言で再挑戦したくなるようにする。

対象は料理経験を問わないスマートフォン利用者。PC・タブレットも同じルール。会員登録なしで調理と画像保存を行える。ランキングの公開名入力は遊んだ後。

## 2. プレイの順序

1. タイトルで「目玉焼きを焼く」。
2. 卵と目標の焼き加減を選ぶ。
3. タップ2回で卵を割る。殻を開き、パンへ落とす。
4. 中火から開始。火力とふたを操作し、目・音・補助表示で変化を見る。
5. 「お皿にうつす」で焼き上がりを確定。90秒で自動的に取り出す。
6. 得点、3項目の評価、改善の一言と自分の目玉焼きを表示。
7. 再挑戦、画像保存、X共有、ランキング登録、商品紹介へ進める。

操作や画面遷移の途中に広告を割り込ませない。音量、画質、チュートリアルは後から変更できる。

## 3. 状態遷移

| 状態 | 入力 | 次の状態・処理 |
|---|---|---|
| TITLE | 開始 | SELECT |
| SELECT | 卵と目標を決定 | CRACK_READY：パンは初期状態、調理時計は停止 |
| CRACK_READY | タップ1回 | CRACKED：殻にひび |
| CRACKED | タップ1回 | DROP：0.8秒の落下演出、再入力無効 |
| DROP | 卵がパンに着地 | COOKING：T=.25、中火、ふた開、W/Y/B/D=0 |
| COOKING | 火力・ふた | 熱と焼き加減を更新 |
| COOKING | お皿にうつす / 90秒経過 | PLATING：モデルを即時固定、run終了は一度だけ |
| PLATING | 0.8秒経過 | RESULT：採点、結果画像の準備 |
| RESULT | もう一度 | SELECT：前回の選択を保持 |
| RESULT | ランキングを見る | RANKING：前回と同じ区分 |
| TITLE / RESULT | 設定 | SETTINGS：閉じると元画面へ |
| COOKING | 一時停止・タブ非表示 | PAUSED：熱、時間、音を停止。復帰後に明示的な再開 |
| PAUSED | 続ける | 直前のCOOKINGへ。隠れていた時間は加算しない |
| PAUSED | 最初から | 確認後SELECT。中断runは公開記録にしない |

コンテキストロストはPAUSEDと同じ扱い。描画の復旧または2Dへの切り替え後に再開する。採点確定後の一時停止や画面回転で値を変更しない。

## 4. 初期の卵

| ID | 画面名 | 見た目 | gameSpeed | カード説明 |
|---|---|---|---|---|
| white | 白い卵 | 白い殻、標準サイズ | 1.00 | まずはこの一個から。 |
| brown | 赤い卵 | 茶色の殻、標準サイズ | 1.00 | 殻の色を変えて、もうひと皿。 |
| quail | うずら卵 | まだら模様、小さい卵 | 1.25 | 小さな一個を、手ぎわよく。 |

白と赤は同じ調理係数。gameSpeedは実際の食材比較ではなく、ゲームのテンポ用の仮設定。3Dモデルの小ささとゲーム速度以外の品質差を暗示しない。全て最初から選べる。うずらも1プレイ1個とし、複数卵の同時調理は拡張に回す。

協賛商品はこの表の表示名・画像・説明を正式な提供情報で差し替える。協賛商品を使うだけで点数が高くなる設計にしない。

## 5. 焼き加減と初期モデル

ゲーム専用の簡易モデル。実際の食品の温度・殺菌・安全性・調理時間は計算しない。実物の調理ガイドとして表示しない。

### モデル変数

T=パンの熱、W=白身の固まり、Y=黄身の固まり、B=縁の焼き色、D=焦げ。全て0〜1。tは調理の経過秒。初期値T=.25、その他0。

heatTargetは切0、弱.38、中.65、強1.0。lidは開0・閉1。eggSpeedは上表。固定ステップdt=1/60秒。

各ステップで下記の順序を守る。W/Y/B/Dの右辺判定には更新前のWを使う。clamp01(x)は0〜1に収める。

```text
oldW = W
T = clamp01(T + (heatTarget - T) * (1 - exp(-dt / 3)))
W = clamp01(W + dt * eggSpeed * 0.055 * T * (1 + 0.18 * lid))
Y = clamp01(Y + dt * eggSpeed * 0.019 * T * (1 + 0.70 * lid))
if oldW >= 0.55:
  B = clamp01(B + dt * eggSpeed * 0.020 * max(0, (T - 0.35) / 0.65) * (1 - 0.40 * lid))
if oldW >= 0.60:
  D = clamp01(D + dt * eggSpeed * 0.028 * max(0, (T - 0.78) / 0.22))
t = t + dt
```

「切」にしてもTはゆっくり下がるため余熱が残る。焼き色は焦げと別に扱う。ふたを閉じると白身も少し速く、黄身はさらに速く進む。この初期モデルは体験調整の出発点。将来変更する場合はscoringVersionを更新する。

### 目標と採点

| 選択 | targetY | 意味 |
|---|---|---|
| とろり | 0.38 | つやのある黄身を目指す |
| ほどよく | 0.62 | やわらかく固まり始めた黄身を目指す |
| しっかり | 0.86 | しっかり固まった黄身を目指す |

```text
whiteFit = clamp01(W / 0.90)
yolkFit = clamp01(1 - max(0, abs(Y - targetY) - 0.06) / 0.30)
brownFit = whiteFit * clamp01(1 - max(0, abs(B - 0.22) - 0.12) / 0.60)
raw = (40 * whiteFit + 40 * yolkFit + 20 * brownFit) * (1 - 0.90 * D)
if W < 0.75: raw = min(raw, 39)
if D >= 0.50: raw = min(raw, 49)
score = round(clamp(raw, 0, 100))
```

結果では「白身40・黄身40・焼き色20」の基礎得点と、焦げ減点または得点上限の適用を別表示する。基礎得点の見せ方で合計と最終点を取り違えさせない。丸めは最終点で行う。

| 点数 | 見出し | 一言の例 |
|---|---|---|
| 90〜100 | 理想のひと皿！ | 白身と黄身、いいバランス。 |
| 75〜89 | いい焼き上がり！ | 次は少し早めにお皿へ。 |
| 50〜74 | もうひと息！ | 火を少し弱めてみよう。 |
| 0〜49 | 次の一個で、もう一度。 | 白身が白くなってから仕上げよう。 |

一言は固定ではなく失点原因から選ぶ。優先順は白身不足→強い焦げ→黄身不足/過剰→焼き色。ブランドの卵が悪いという表現はしない。

### チューニング検証

- 卵3種×目標3種で90点以上が可能であること。
- ふたなし中火でも成功できる時間帯があること。
- 高火力の放置は明確に焦げること。
- 同じ操作を同じstepで適用すれば、描画FPSが違っても同じ点数になること。
- 操作ログは整数stepで記録。同stepに複数操作がある場合はseq順で適用。
- 初回には「白身の透明感がなくなるまで待とう」「ふたをすると黄身が進みやすい」の補助を表示。正解時刻のカウントダウンは出さない。

## 6. 画面設計

### 01 タイトル

メインビジュアルを上〜中央に大きく見せる。クリーム色、木のカウンター、朝の光、黄身のオレンジを使用。「たまご日和」「じゅわっ、とろっ。今日のひと皿。」「目玉焼きを焼く」を優先。副導線にランキングと遊び方。協賛がある場合のみ小さく「PR・提供：企業名」。

### 02 卵・目標選択

卵3枚を縦リストで並べ、画像・名前・短文をセットにする。選択は深緑の枠とチェックを併用。下段に目標3種をボタンで並べる。「この卵で焼く」を固定フッターに置くが、本文末尾に同じ高さの余白を設ける。戻ることで選択内容を保持。

### 03 割る

卵はパンの上に大きく浮かせる。下に「タップして、ひびを入れる」→「もう一度タップして、割る」。タップ領域全体が明確なbutton。音なしでもひびの変化と文字で操作が分かる。

### 04 調理

上段：戻る代わりに一時停止、選択した卵、目標、音ボタン。時計は経過時間「00:32」、制限時間の焦りを主役にしない。

中央：3Dのパンと卵。PCは横幅を生かし、縦画面はパンの直径を大きく保つ。カメラの画角を調整して、単純な切り抜きで卵が隠れないようにする。

下段：白身/黄身の短い観察ラベル、火力4ボタン、ふた開閉、「お皿にうつす」。火力変更は即座にUIへ反映し、熱と音は遅れて変化する。

状態ラベルはモデルの範囲から算出する。例：W<.4「まだ透明」、.4〜.75「白くなってきた」、.75以上「白身が固まってきた」。黄身は「とろり」「固まりはじめ」「しっかり」。ラベル自体を現実の安全判定にしない。

### 05 結果

自分の出来た目玉焼き、点数、称号、選択した卵と目標、3項目評価、改善の一言。最優先は「もう一度焼く」。その次に「Xにポスト」「画像を保存」、対応時のみ「画像を共有」。ランキング登録は任意。PR商品カードは操作群の後に置く。

### 06 ランキング

週間を初期表示、全期間へ切替可。現在の卵と目標を選べる。順位、表示名、点数、自分の行を強調。期間の開始・終了日を日本時間で表示。未登録なら「この条件で記録をつくろう」、未参加0件なら「最初のひと皿を投稿しよう」。

## 7. レスポンシブと操作

| 環境 | 配置 |
|---|---|
| 幅320〜599pxの縦 | 上部HUD、中央シーン、下部操作。ボタン高さ48〜56px |
| 高さ500px以下の横 | 左側シーン、右側250〜300px操作パネル。内容が溢れる場合は縦スクロール可能 |
| 幅600〜1023px | 中央寄せ最大幅、十分な上下余白。横では2列 |
| 幅1024px以上 | 左に大きなシーン、右320pxの操作パネル。最大1280px |

タップ、クリック、キーボードで同じ操作。火力0/1/2/3、ふたL、盛り付けS、停止P。フォーム入力中はショートカット無効。キー長押しやpointerdown+clickの重複を処理し、アニメーション中の二重操作を防ぐ。

pinch zoomをページ全体で禁止しない。ドラッグなしで完結。ホバー必須にしない。タッチ対象は最低48×48px、隣接対象間は8px。フォーカスを見せ、ボタンにラベルを付け、toggleはaria-pressed、結果は適切なaria-live。色だけで良否を伝えない。動きの低減時はカメラ揺れ・跳ね・粒子を抑える。音量0でも全機能を使える。

## 8. 性能と互換性の目標

- 対象：公開時点の主要ブラウザの現行版と直前版。全ての古い機器・アプリ内ブラウザの保証はしない。
- モバイル30fps、PC60fpsを目標。計測端末と結果をREADMEに残す。
- 初回転送5MB程度、3Dジオメトリは約5万三角形以下、draw callは80程度以下を初期予算とする。品質目標であり実測が必要。
- DPR上限1.5、低品質1。リアルタイム影は1枚まで、重ければ接地影テクスチャへ。湯気最大20枚、ポストエフェクトは必須にしない。
- 素材PNGは元データ。実装時に適切なサイズ/WebP等へ最適化し、元画像は保持する。
- 画像・音の欠落で黒画面にしない。PRやランキング取得を待たずに開始できる。
- 音声再生不可は静音に切替。localStorage不可ならメモリ内の結果だけ保持して説明する。
- オフラインで新規ロードまで保証する場合だけService Workerを追加。初期段階では「読込後のローカル調理が続く」を保証範囲とする。

## 11. この設計で確認したこと

初期係数の数値シミュレーションで、3卵×3目標の全9条件に100点を取れる操作があることを確認。以下は中火を維持した場合の一例であり、実際の調理時間ではありません。時間はゲーム内で卵がパンに着地した時点からです。

| 卵 | とろり・ふた開 | ほどよく・ふた開 | しっかり・ふた閉 |
|---|---|---|---|
| 白い卵 | 約27.6秒で100点 | 約46.9秒で100点 | 約39.8秒で100点 |
| 赤い卵 | 約27.6秒で100点 | 約46.9秒で100点 | 約39.8秒で100点 |
| うずら卵 | 約22.4秒で100点 | 約37.9秒で100点 | 約32.2秒で100点 |

未加熱の初期状態が0点、白身不足と強い焦げに得点上限が適用されることも確認済み。画面見本はPC用のブラウザ描画で6画面の切れ・重なりと幅390px時の横方向のはみ出しを確認しています。

ゲーム本体、端末実機、実際のX投稿、公開ランキング、広告計測は未実装・未検証です。上記は設計と初期計算モデルの確認であり、本番の動作確認を代替しません。
