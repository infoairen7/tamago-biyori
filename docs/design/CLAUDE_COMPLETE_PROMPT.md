# 資料：01_CLAUDE_BUILD_PROMPT.md

# Claude用・制作開始プロンプト

以下を制作指示として実行してください。

あなたはブラウザ3Dゲームのエンジニア兼UI実装者です。添付資料を使い、日本語ゲーム「たまご日和」を実装してください。タイトルは仮称です。企画の説明だけで終わらず、起動できるソースコードとREADMEを作ってください。

## 1. 目的と完成像

プレイヤーが料理人の主観視点で、小さな目玉焼き専用フライパンに卵を割り、火加減とふたを調整して仕上げます。出来栄えを0〜100点で採点し、出来た目玉焼きの画像と結果をXで共有でき、オンラインの週間ランキングに参加できます。おいしそうな見た目・焼ける音・再挑戦の気軽さから「目玉焼きを食べたい」につなげ、結果画面に卵企業の商品紹介を自然に置きます。

1回の調理は目安30〜60秒、調理上限90秒。選択や結果閲覧の時間は含みません。実際の調理温度・時間の指南には使わない、短縮したゲーム表現です。

## 2. 入力資料の優先度

1. 本指示書と02_GAME_UX_SPEC.mdのゲームルール。
2. 03_ONLINE_AND_BRAND.mdのオンライン仕様。
3. game-config.json / design-tokens.json。
4. UI_DESIGN.htmlとPNG画面見本の見た目。

画像見本の数値や人物名はサンプルです。サンプルのランキングを公開ランキングとして表示しないでください。資料間に矛盾があれば数値設定とゲームルールを確認して実装判断を明記してください。

## 3. 技術構成

- 原則TypeScript、Vite、React、Three.jsのWebGLRenderer。インストール時の安定版を確認して互換性のある組み合わせを固定し、lockfileを含める。
- UIはHTML/CSS。ゲーム内の日本語を3Dテクスチャに焼き込まない。
- 描画非依存のGameModelに状態遷移・熱・焼き加減・採点を置く。3DとCanvas 2Dは同じモデルを読む。
- WebGL 2の利用可否を検出し、初期化失敗・重大な描画失敗では軽量2Dへ。コンテキストを失った瞬間にシミュレーションを止め、同じ状態から再開する。
- WebGPU、専用アプリ、VR、ポインターロックを必須にしない。
- スマートフォン縦持ちが基準。横持ち、タブレット、PCにも対応。向きの固定や全画面許可を必須にしない。
- 音は開始ボタンなどユーザー操作後に有効化する。初期設定は控えめ。音なしでも遊べる。
- サーバーがない環境では遊べるローカル版を作る。オンライン機能はインターフェースを分離し、未接続を明示する。

## 4. 必須画面

タイトル / 卵・焼き加減選択 / 卵を割る / 調理 / 結果 / ランキング / 設定・遊び方。ランキング登録、商品詳細、共有はダイアログまたはシートでよい。

画面の文章、操作領域、空状態、失敗時の振る舞いは仕様書を参照。390×844を基準に、320px幅でも横スクロールなし。主要ボタン48px以上、最終「お皿にうつす」は56px以上。safe-area、100dvh、文字拡大に対応する。

## 5. 調理体験

- 固定した主観視点でフライパンを見下ろす。歩行や視点移動はなし。パンはプレイ領域の55〜70%を使い、黄身と白身を大きく見せる。
- 卵は白い卵・赤い卵・うずら卵の3種類。白と赤で品質・栄養・点数優遇を捏造しない。初期性能は同じ。うずらは小さく、ゲーム上の進行だけ少し速い。
- 開始前に「とろり / ほどよく / しっかり」の目標を選ぶ。どれも満点を狙える。
- 卵を1回タップでひび、もう1回で割る。Enter/Spaceでも操作可。殻が開き白身と黄身がパンへ落ちる短いアニメーション。入力連打で卵を重複生成しない。割り方の点数・失敗は設けず、焼き加減に集中させる。
- 卵が落ちた時点で調理開始。中火が初期値。火力は「切 / 弱 / 中 / 強」の4つの大きなボタン。
- ふたは開閉トグル。蒸し焼きで黄身の進行が速くなる。透明ガラス、または補助ラベルで状態を把握できる。
- 火を切っても余熱は残る。「お皿にうつす」で採点を確定し、それ以降のアニメーション中は値を変えない。
- 白身の透明→白、縁の黄金色→焦げ、黄身のつや→マットへの変化、微細な泡、湯気をモデル値に連動させる。実際の結果画像も同じ状態から作る。
- ゲームモデルは固定ステップ1/60秒。端末FPSで採点結果を変えない。乱数を使う形状はrun seedで固定。
- バックグラウンド移行で一時停止。復帰後に再開ボタンを押すまで熱を進めない。長時間の差分をまとめて加算しない。

## 6. 採点・ランキング

02_GAME_UX_SPEC.mdの式を実装。白身40点＋黄身40点＋焼き色20点。生の白身と強い焦げには総点上限を適用。卵を割る速さ、課金、広告閲覧、端末性能は採点対象にしない。

全種類・全目標で90点以上を取れることをシミュレーションで確認する。設定調整はconfigだけで行う。採点バージョンを必ず記録する。

オンラインではサーバー発行のrunIdと操作ログを送り、サーバー側の同一モデルで再計算する。クライアントのscore値をランキングに直接保存しない。実装するDB、API、入力検証、重複送信対策を明示する。異常なログや期限切れは拒否し、ローカルの遊びは維持する。

ランキングは卵種×目標×採点バージョン×週で分け、同条件で比較。各参加者は同区分で自己ベスト1件。サーバー未接続のときは「ランキングに接続できません」を表示し、架空の参加者で埋めない。

## 7. X共有と企業PR

- 「Xにポスト」：結果テキスト＋公開URL＋ハッシュタグをWeb Intentで開く。URLSearchParamsで正しくエンコードし、投稿はユーザーが確定する。
- 結果画像を1200×630 PNGで生成し、プレビュー・保存ボタンを用意する。ユーザー自身の結果の目玉焼きを大きく載せる。
- Web Share APIでファイルを共有できる環境のみ「画像を共有」を表示。Xが共有先に現れることや画像・文言が同時に引き継がれることを保証しない。
- Web Intentにローカル画像を自動添付できると実装しない。画像保存→Xで添付する案内を用意する。
- 未公開時は存在しないURLを投稿文に入れない。画像生成や共有のキャンセルでゲーム結果を失わない。
- 協賛企業の設定はsponsor-config.example.jsonを基に差し替える。調理中に広告モーダルを出さない。結果画面に「今度は、本物のたまごで。」の自然な導線と「PR」表示を入れる。
- 商品データが未設定のときはPR枠を非表示。実在の商品特徴、受賞歴、効能、購入先を創作しない。

## 8. 素材

assets/hero.pngはタイトル用・質感参考です。完成イラストを調理中ずっと貼り付けて3D実装の代わりにしないでください。

卵PNGは選択カード用。3Dのフライパン・卵・殻・ふた・皿・キッチンはプロシージャル形状で実装できること。外部GLBや音源なしでも起動可能にする。04_ASSET_GUIDE.mdにモデルと音の制作指示があります。画像ファイルが渡されていない場合は欠落を伝え、コードで仮表示を作り、差し替えパスを残してください。

## 9. 実装順序と完了条件

### 段階1：ローカルで遊べる完成形

タイトル→卵選択→割る→調理→採点→再挑戦を完成させる。設定、ローカル自己ベスト、3D/2D、音量・一時停止を含める。画面だけで終了しない。ランダムに点数を付けない。

### 段階2：シェアとPR

プレイ結果から画像生成、X投稿画面、画像保存、対応端末で画像共有、協賛企業設定による表示切り替え。失敗時のUIを含める。

### 段階3：公開ランキング

永続DBとサーバーAPI、匿名プレイヤー識別、操作ログ再計算、入力検証、週区切り、公開登録、取得、自己ベスト更新。未接続時のローカルモードを残す。接続先が無ければバックエンドのコード・スキーマ・設定手順まで出し、未稼働の機能を稼働済みと言わない。

### 段階4：調整と実機確認

320pxスマホ、iOS Safari、Android Chrome、PC Chrome/Edge/Firefox/Safariを対象に、利用できる範囲で確認。実機未確認は区別して報告する。iOSの音、ページ復帰、縦横切り替え、3D不能時の2D、共有未対応、オフライン、二重送信、低FPSで同スコアを重点確認する。

## 10. 成果物と確認

- ファイル構成、インストール・起動・ビルド手順、環境変数例、オンライン設定手順。
- プロダクションビルドが成功し、主要遷移で例外がないこと。
- 同じ操作ログは30/60/120fpsの描画でも同じ点数。0〜100点から逸脱しない。生・焦げの上限、時間上限、停止後の不変をテスト。
- ランキングの任意スコア送信、run再利用、異常step、別ユーザーのrun送信が拒否されること。

まず現在の作業環境でできる範囲を短く示し、段階1の実装から着手してください。小さな実装判断は自分で行い、不要な質問で止まらないでください。

# 資料：02_GAME_UX_SPEC.md

# たまご日和 — ゲーム・UI/UX仕様

制作基準日：2026-09-27 / バージョン：設計1.0 / 仮タイトル

## 1. 体験の核

「じゅわっ、とろっ。今日のひと皿。」

目の前の卵が目玉焼きになる小さな気持ちよさを、タップ中心で楽しむ。料理の正解を一つにせず、選んだ焼き加減へ近づける遊びとする。短い1プレイ、見た目から分かる変化、結果に応じた一言で再挑戦したくなるようにする。

対象は料理経験を問わないスマートフォン利用者。PC・タブレットも同じルール。会員登録なしで調理と画像保存を行える。ランキングの公開名入力は遊んだ後。

## 2. プレイの順序

1. タイトルで「目玉焼きを焼く」。
2. 卵と目標の焼き加減を選ぶ。
3. タップ2回で卵を割る。殻を開き、パンへ落とす。
4. 中火から開始。火力とふたを操作し、目・音・補助表示で変化を見る。
5. 「お皿にうつす」で焼き上がりを確定。90秒で自動的に取り出す。
6. 得点、3項目の評価、改善の一言と自分の目玉焼きを表示。
7. 再挑戦、画像保存、X共有、ランキング登録、商品紹介へ進める。

操作や画面遷移の途中に広告を割り込ませない。音量、画質、チュートリアルは後から変更できる。

## 3. 状態遷移

| 状態 | 入力 | 次の状態・処理 |
|---|---|---|
| TITLE | 開始 | SELECT |
| SELECT | 卵と目標を決定 | CRACK_READY：パンは初期状態、調理時計は停止 |
| CRACK_READY | タップ1回 | CRACKED：殻にひび |
| CRACKED | タップ1回 | DROP：0.8秒の落下演出、再入力無効 |
| DROP | 卵がパンに着地 | COOKING：T=.25、中火、ふた開、W/Y/B/D=0 |
| COOKING | 火力・ふた | 熱と焼き加減を更新 |
| COOKING | お皿にうつす / 90秒経過 | PLATING：モデルを即時固定、run終了は一度だけ |
| PLATING | 0.8秒経過 | RESULT：採点、結果画像の準備 |
| RESULT | もう一度 | SELECT：前回の選択を保持 |
| RESULT | ランキングを見る | RANKING：前回と同じ区分 |
| TITLE / RESULT | 設定 | SETTINGS：閉じると元画面へ |
| COOKING | 一時停止・タブ非表示 | PAUSED：熱、時間、音を停止。復帰後に明示的な再開 |
| PAUSED | 続ける | 直前のCOOKINGへ。隠れていた時間は加算しない |
| PAUSED | 最初から | 確認後SELECT。中断runは公開記録にしない |

コンテキストロストはPAUSEDと同じ扱い。描画の復旧または2Dへの切り替え後に再開する。採点確定後の一時停止や画面回転で値を変更しない。

## 4. 初期の卵

| ID | 画面名 | 見た目 | gameSpeed | カード説明 |
|---|---|---|---|---|
| white | 白い卵 | 白い殻、標準サイズ | 1.00 | まずはこの一個から。 |
| brown | 赤い卵 | 茶色の殻、標準サイズ | 1.00 | 殻の色を変えて、もうひと皿。 |
| quail | うずら卵 | まだら模様、小さい卵 | 1.25 | 小さな一個を、手ぎわよく。 |

白と赤は同じ調理係数。gameSpeedは実際の食材比較ではなく、ゲームのテンポ用の仮設定。3Dモデルの小ささとゲーム速度以外の品質差を暗示しない。全て最初から選べる。うずらも1プレイ1個とし、複数卵の同時調理は拡張に回す。

協賛商品はこの表の表示名・画像・説明を正式な提供情報で差し替える。協賛商品を使うだけで点数が高くなる設計にしない。

## 5. 焼き加減と初期モデル

ゲーム専用の簡易モデル。実際の食品の温度・殺菌・安全性・調理時間は計算しない。実物の調理ガイドとして表示しない。

### モデル変数

T=パンの熱、W=白身の固まり、Y=黄身の固まり、B=縁の焼き色、D=焦げ。全て0〜1。tは調理の経過秒。初期値T=.25、その他0。

heatTargetは切0、弱.38、中.65、強1.0。lidは開0・閉1。eggSpeedは上表。固定ステップdt=1/60秒。

各ステップで下記の順序を守る。W/Y/B/Dの右辺判定には更新前のWを使う。clamp01(x)は0〜1に収める。

```text
oldW = W
T = clamp01(T + (heatTarget - T) * (1 - exp(-dt / 3)))
W = clamp01(W + dt * eggSpeed * 0.055 * T * (1 + 0.18 * lid))
Y = clamp01(Y + dt * eggSpeed * 0.019 * T * (1 + 0.70 * lid))
if oldW >= 0.55:
  B = clamp01(B + dt * eggSpeed * 0.020 * max(0, (T - 0.35) / 0.65) * (1 - 0.40 * lid))
if oldW >= 0.60:
  D = clamp01(D + dt * eggSpeed * 0.028 * max(0, (T - 0.78) / 0.22))
t = t + dt
```

「切」にしてもTはゆっくり下がるため余熱が残る。焼き色は焦げと別に扱う。ふたを閉じると白身も少し速く、黄身はさらに速く進む。この初期モデルは体験調整の出発点。将来変更する場合はscoringVersionを更新する。

### 目標と採点

| 選択 | targetY | 意味 |
|---|---|---|
| とろり | 0.38 | つやのある黄身を目指す |
| ほどよく | 0.62 | やわらかく固まり始めた黄身を目指す |
| しっかり | 0.86 | しっかり固まった黄身を目指す |

```text
whiteFit = clamp01(W / 0.90)
yolkFit = clamp01(1 - max(0, abs(Y - targetY) - 0.06) / 0.30)
brownFit = whiteFit * clamp01(1 - max(0, abs(B - 0.22) - 0.12) / 0.60)
raw = (40 * whiteFit + 40 * yolkFit + 20 * brownFit) * (1 - 0.90 * D)
if W < 0.75: raw = min(raw, 39)
if D >= 0.50: raw = min(raw, 49)
score = round(clamp(raw, 0, 100))
```

結果では「白身40・黄身40・焼き色20」の基礎得点と、焦げ減点または得点上限の適用を別表示する。基礎得点の見せ方で合計と最終点を取り違えさせない。丸めは最終点で行う。

| 点数 | 見出し | 一言の例 |
|---|---|---|
| 90〜100 | 理想のひと皿！ | 白身と黄身、いいバランス。 |
| 75〜89 | いい焼き上がり！ | 次は少し早めにお皿へ。 |
| 50〜74 | もうひと息！ | 火を少し弱めてみよう。 |
| 0〜49 | 次の一個で、もう一度。 | 白身が白くなってから仕上げよう。 |

一言は固定ではなく失点原因から選ぶ。優先順は白身不足→強い焦げ→黄身不足/過剰→焼き色。ブランドの卵が悪いという表現はしない。

### チューニング検証

- 卵3種×目標3種で90点以上が可能であること。
- ふたなし中火でも成功できる時間帯があること。
- 高火力の放置は明確に焦げること。
- 同じ操作を同じstepで適用すれば、描画FPSが違っても同じ点数になること。
- 操作ログは整数stepで記録。同stepに複数操作がある場合はseq順で適用。
- 初回には「白身の透明感がなくなるまで待とう」「ふたをすると黄身が進みやすい」の補助を表示。正解時刻のカウントダウンは出さない。

## 6. 画面設計

### 01 タイトル

メインビジュアルを上〜中央に大きく見せる。クリーム色、木のカウンター、朝の光、黄身のオレンジを使用。「たまご日和」「じゅわっ、とろっ。今日のひと皿。」「目玉焼きを焼く」を優先。副導線にランキングと遊び方。協賛がある場合のみ小さく「PR・提供：企業名」。

### 02 卵・目標選択

卵3枚を縦リストで並べ、画像・名前・短文をセットにする。選択は深緑の枠とチェックを併用。下段に目標3種をボタンで並べる。「この卵で焼く」を固定フッターに置くが、本文末尾に同じ高さの余白を設ける。戻ることで選択内容を保持。

### 03 割る

卵はパンの上に大きく浮かせる。下に「タップして、ひびを入れる」→「もう一度タップして、割る」。タップ領域全体が明確なbutton。音なしでもひびの変化と文字で操作が分かる。

### 04 調理

上段：戻る代わりに一時停止、選択した卵、目標、音ボタン。時計は経過時間「00:32」、制限時間の焦りを主役にしない。

中央：3Dのパンと卵。PCは横幅を生かし、縦画面はパンの直径を大きく保つ。カメラの画角を調整して、単純な切り抜きで卵が隠れないようにする。

下段：白身/黄身の短い観察ラベル、火力4ボタン、ふた開閉、「お皿にうつす」。火力変更は即座にUIへ反映し、熱と音は遅れて変化する。

状態ラベルはモデルの範囲から算出する。例：W<.4「まだ透明」、.4〜.75「白くなってきた」、.75以上「白身が固まってきた」。黄身は「とろり」「固まりはじめ」「しっかり」。ラベル自体を現実の安全判定にしない。

### 05 結果

自分の出来た目玉焼き、点数、称号、選択した卵と目標、3項目評価、改善の一言。最優先は「もう一度焼く」。その次に「Xにポスト」「画像を保存」、対応時のみ「画像を共有」。ランキング登録は任意。PR商品カードは操作群の後に置く。

### 06 ランキング

週間を初期表示、全期間へ切替可。現在の卵と目標を選べる。順位、表示名、点数、自分の行を強調。期間の開始・終了日を日本時間で表示。未登録なら「この条件で記録をつくろう」、未参加0件なら「最初のひと皿を投稿しよう」。

## 7. レスポンシブと操作

| 環境 | 配置 |
|---|---|
| 幅320〜599pxの縦 | 上部HUD、中央シーン、下部操作。ボタン高さ48〜56px |
| 高さ500px以下の横 | 左側シーン、右側250〜300px操作パネル。内容が溢れる場合は縦スクロール可能 |
| 幅600〜1023px | 中央寄せ最大幅、十分な上下余白。横では2列 |
| 幅1024px以上 | 左に大きなシーン、右320pxの操作パネル。最大1280px |

タップ、クリック、キーボードで同じ操作。火力0/1/2/3、ふたL、盛り付けS、停止P。フォーム入力中はショートカット無効。キー長押しやpointerdown+clickの重複を処理し、アニメーション中の二重操作を防ぐ。

pinch zoomをページ全体で禁止しない。ドラッグなしで完結。ホバー必須にしない。タッチ対象は最低48×48px、隣接対象間は8px。フォーカスを見せ、ボタンにラベルを付け、toggleはaria-pressed、結果は適切なaria-live。色だけで良否を伝えない。動きの低減時はカメラ揺れ・跳ね・粒子を抑える。音量0でも全機能を使える。

## 8. 性能と互換性の目標

- 対象：公開時点の主要ブラウザの現行版と直前版。全ての古い機器・アプリ内ブラウザの保証はしない。
- モバイル30fps、PC60fpsを目標。計測端末と結果をREADMEに残す。
- 初回転送5MB程度、3Dジオメトリは約5万三角形以下、draw callは80程度以下を初期予算とする。品質目標であり実測が必要。
- DPR上限1.5、低品質1。リアルタイム影は1枚まで、重ければ接地影テクスチャへ。湯気最大20枚、ポストエフェクトは必須にしない。
- 素材PNGは元データ。実装時に適切なサイズ/WebP等へ最適化し、元画像は保持する。
- 画像・音の欠落で黒画面にしない。PRやランキング取得を待たずに開始できる。
- 音声再生不可は静音に切替。localStorage不可ならメモリ内の結果だけ保持して説明する。
- オフラインで新規ロードまで保証する場合だけService Workerを追加。初期段階では「読込後のローカル調理が続く」を保証範囲とする。

# オンライン・X共有・企業PRの仕様

## 1. Xへの投稿

基本動線は「結果を確認 → Xにポスト → Xの投稿画面で本人が投稿」。自動投稿やXログインをゲーム開始の条件にしない。

投稿文の例：

```text
目玉焼き、今日は96点！
白い卵 × とろりで「理想のひと皿！」
あなたは何点？
#たまご日和 #目玉焼きチャレンジ
[公開ゲームURL]
```

`https://x.com/intent/tweet` にtext、url、hashtagsをURLSearchParamsで設定する。hashtagsは「#」を除くカンマ区切り。公開URLは設定値から取得し、未設定時は付けない。最終の文面や改行が投稿画面でどう引き継がれるかを公開前に実機確認する。

Web IntentだけでローカルPNGを添付する仕様にはしない。次の手段を並べる。

| 手段 | ユーザーの操作 | 留意点 |
|---|---|---|
| Xにポスト | テキストとリンクを持ってXへ | 画像の自動添付は前提にしない |
| 画像を保存 | 結果PNGを保存し、Xで添付 | downloadが機能しない環境では画像を開き保存方法を案内 |
| 画像を共有 | OSの共有画面から送信先を選ぶ | HTTPS、share/canShareの有無、ファイル対応を検出。Xが選べるとは限らない |
| 結果の文をコピー | 投稿文をクリップボードへ | Clipboard不可なら選択できるテキストを表示 |

結果画面で先にPNG Blob/Fileを用意し、ユーザーのタップから直ちにnavigator.shareを呼べるようにする。準備中は「画像を準備中」。長い非同期処理でユーザー操作の有効性を失わせない。canShare({files:[file]})でファイル対応を確認し、AbortErrorはキャンセル扱い、その他の失敗は保存へ誘導する。

実際の投稿完了はWeb Intentや共有画面の起動から判定できない。計測名は「投稿画面を開いた」「共有画面を開いた」とし、投稿数と呼ばない。

## 2. 結果画像

1200×630pxのPNG。安全余白48px。左約65%にそのプレイの卵と皿、右に点数、称号、卵種と目標、下にゲーム名と任意の提供ロゴ。画面のボタンや入力欄は含めない。

採点確定時のW/Y/B/Dとseedを保持し、同じ状態からオフスクリーンのシーンを描画して2D canvasに合成する。UIスクリーンショットをそのまま切り取らない。低メモリ端末では600×315に落として保存できる。日本語の文字描画はフォントの読込完了を待つ。

画像への公開名掲載は初期オフ。スコアがローカル未検証なら共有画像に順位を付けない。オンラインでも投稿時点の順位と取得時刻を示し、後に変化し得るものとして扱う。

外部の商品画像は同一オリジンで配信するかCORS対応を確認し、canvasが汚染されないようにする。画像読込失敗時は商品画像を省いて結果PNGを作る。常時preserveDrawingBufferを有効にして性能を落とさず、専用描画または描画直後のcaptureを用いる。

結果ごとの公開URL・動的OGPは後続拡張。導入する場合はサーバーで結果ページと公開画像を返し、クローラーがJavaScriptを実行しなくてもメタ情報を読めるようにする。初期は共通ゲームURLと画像保存で成立させる。

## 3. ランキングの構成

公開ランキングにはサーバーと永続DBが必要。localStorageは端末内の自己ベスト専用。

区分キー：scoringVersion + eggId + targetId + period。週間は日本時間の月曜00:00〜次の月曜00:00、全期間も用意する。日時はDBではUTCで持ち、画面と期間判定はAsia/Tokyo。週への所属はサーバー検証完了時刻で決める。

「週間・白い卵・とろり」など区分を常に明示。全種類を混ぜた優劣は初期には作らない。各匿名プレイヤーの区分内自己ベスト1件。匿名識別は同一人物を完全に識別できず、Cookie消去・別端末は別参加者になり得る。賞品付きキャンペーンを行う段階では本人確認等を別途設計する。

同点は同順位の競技順位方式：1、1、3。行の並びは先に達成したサーバー日時、最後にresultIdで安定化。週間切り替え後も古い記録を上書きしない。

## 4. APIとデータ

| API例 | 役割 |
|---|---|
| POST /api/runs | eggId/targetIdを受け、runId・seed・scoringVersion・有効期限を発行 |
| POST /api/runs/:id/finish | 操作ログと終了stepを受け、検証・再計算・結果固定。クライアントscoreは採用しない |
| POST /api/results/:id/publish | 同一セッションの結果を、表示名を確認して公開登録 |
| GET /api/leaderboard | 卵・目標・バージョン・期間で絞り、上位50件と自分の記録を返す |

公開名・ランキング掲載は任意。ゲームのスコア算出と公開登録を分ける。公開しない結果も手元で共有できる。

```text
players: id, createdAt, sessionCredentialHash
runs: id, playerId, eggId, targetId, seed, scoringVersion, startedAt, expiresAt, status
results: id, runId(unique), playerId, eggId, targetId, scoringVersion,
         W, Y, B, D, score, stopStep, verifiedAt, publishedAt(nullable), displayName(nullable)
events: runId, seq, step, action, value  // 必要な検証期間だけ保持する運用を設ける
```

操作例：`{seq:0,step:240,action:"heat",value:"low"}`。stepは0以上5400以下の整数。actionはheat/lidのみ、停止はstopStep。pauseは調理stepを増やさない。暗号鍵をクライアントへ置かない。

## 5. 検証と保存

- セッションの匿名プレイヤーとrunをサーバーで紐付ける。別プレイヤーのrunを終了・公開できないこと。
- 有効期限は発行から15分を初期値。ネットワーク再試行は同じrunId・同じ操作ログを使用。
- seqは連番、stepは非減少、範囲内、操作は許可リスト。最大500イベント、同じ値の連続記録を除去する。多すぎる場合は正当な操作も含め失敗理由を明示。
- stopStepは最終イベント以上、5400以下。調理秒がサーバー実経過より不自然に長い場合は拒否。通信遅延の許容差は設定する。
- サーバー側の同じバージョンのモデルで初期状態から再生し、整数得点を確定。seed、卵、目標はrun発行時の値を使う。
- runId一意制約とトランザクションで二重登録を防止。同じfinishの再送は同じ結果を返し、異なるログへの差し替えは拒否。
- 名前は1〜12書記素、制御文字除去、文字列としてエスケープして表示。入力値をHTMLとして解釈しない。不適切名を非表示・修正できる運営手段を用意する。
- DBへの直接書込権限や秘密鍵をフロントに渡さない。CookieセッションならCSRF対策・SameSite等を設定。CORSとレート制限は公開先に合わせる。
- ローカル開始時にrunを発行できなかったプレイはローカル専用。通信復帰後に検証済み記録へ見せかけない。
- finishが失敗しても結果画面は保持。有効期限内は同じrunを再送可。期限切れはローカル結果として残す。

再計算は任意スコアの直送や不可能なログを防ぐが、成立する操作ログの自動生成や複数アカウントを完全には防げない。賞品付き運用では監視・参加制限など追加対策が必要。

## 6. 企業PR

ゲームで感じた「食べたい」を、正式な商品情報と購入先につなげる。ブランド未定のため設定はenabled:false。社名やリンクが無ければPR枠自体を非表示にする。

| 場所 | 表示 | 目的 |
|---|---|---|
| タイトル下部 | PR・提供：企業名、小さなロゴ | 提供関係を分かりやすくする |
| 卵選択 | 正式商品画像・商品名・承認済みの短い説明 | 商品に親しむ |
| 結果下部 | 今度は、本物のたまごで。＋商品カード＋購入先 | 興味が高まった時に案内 |
| シェア画像端 | 小さな提供ロゴ（設定時のみ） | 結果を主役にした認知拡大 |

課金や広告視聴による得点優遇は入れない。購入をランキング参加の条件にしない。食材の健康効果、殻色による栄養差、根拠のない品質表示は足さない。生成した卵画像を実在商品写真として扱わない。レシピは企業の確認済みページにリンクする。

## 7. 計測

| イベント | 確認したいこと |
|---|---|
| game_start | 何人が調理を開始したか |
| egg_select | 卵の選択比率 |
| game_complete | 完了率、点数分布 |

## 3D制作プロンプト（Claudeに渡す）

```text
添付のhero.pngを、朝の光と食材の質感の参考にしてください。
Three.jsの標準的なgeometryとmaterialで、以下の3Dシーンを制作してください。
カメラは料理人の目線から約50度下向き。操作による歩行や自由旋回なし。
白身と黄身が常に大きく見える構図。パンの柄は画面右下へ。

1. 直径約18cmを想起させる小型の黒い目玉焼き専用フライパン。
   外周・内側・底の段差と木の柄を別形状にし、金属は微細な粗さ。
2. 卵殻は少し先が細い卵型メッシュ。白/赤/うずらの色と斑点を設定から変更。
   2つの殻の半分を左右へ開き、割る動作を0.8秒程度で見せる。
3. 白身は不規則な外周の薄いmesh。Wで透明→不透明へ変化。
   Yで黄身のroughness・色・揺れを変化。黄身はつぶれた半球形。
   Bで縁を黄金色、Dで縁から焦げを表現。形状はseedから決定。
4. ふたは持ち手付きの丸い透明ガラス。閉じても卵が読める。
   透明描画が重い環境では簡略化して、観察ラベルを併用。
5. 木のカウンター、淡いタイル、白い皿、調理器を最小限の形状で構成。
6. 左上から暖かな主光、柔らかな環境光。パンの接地影を入れる。
7. 泡と湯気は少数の軽量パーティクル。減速や画質設定で数を落とす。
8. 結果では同じ卵meshと材質状態を皿へ移す。イラストへの置き換えはしない。

重い物理エンジン、流体シミュレーション、動的反射、外部モデルを必須にしない。
卵の落下・広がりは短い補間アニメーションで表現してください。
```

## 2D切り替え時の制作プロンプト

```text
WebGL 2が使えない環境では、同じGameModelを読むCanvas 2D rendererに切り替える。
楕円のパン、木の柄、不規則な白身、グラデーションの黄身、焼き色リング、湯気を描く。
W/Y/B/Dとseedを3Dと共有し、見た目・入力・採点・画像保存の意味を揃える。
パースと明暗で奥行きを表現し、画面に「軽量表示」を小さく示す。
2Dでも全ての操作とランキング条件を維持し、低画質だから点数を下げない。
```

## 音の制作指示

音源ファイルは今回の同梱対象外。ClaudeではまずWeb Audio等による簡易音、または無音でも動作する構成にする。後から以下のオリジナル効果音へ差し替えられるようにする。

| 音ID | 制作プロンプト・要件 |
|---|---|
| egg_tap | 卵殻を軽く一度たたく乾いた小さな音、0.15秒、余韻なし |
| egg_crack | 卵の殻がぱきっと開く自然な音、0.5秒、破壊音を誇張しない |
| egg_drop | 卵が温かい小型フライパンへ落ちる柔らかな音、0.7秒 |
| sizzle_loop | 目玉焼きがじゅわじゅわ焼ける細かな油の音、4秒ループ、声・音楽なし、接続点が目立たない |
| lid_on/off | ガラスぶたが金属パンへ軽く触れる音、0.4秒、耳障りにしない |
| plate | 目玉焼きが皿へ滑る柔らかな音、0.6秒 |
| result_good | 朝らしい軽い木琴の3音、0.8秒、成功を明るく知らせる |

焼ける音量はTと進行に連動。ふたをすると少しこもる。失敗時に大音量のブザーを鳴らさない。BGMは必須にせず、焼ける音を主役にする。配布する音素材の利用条件は実装時に確認する。

## UIトークンと部品

正確な値はdesign-tokens.jsonを参照。背景#FFF8EB、深緑#244C3A、文字#28392D、黄身色#F5B42A。黄身色上の文字は濃色。淡い黄色の上に白文字を置かない。

角丸16〜20px、余白8の倍数を中心に4/12も使用。本文16px、補助14px、見出し24〜32px、点数64px。タッチ対象48px以上。フォントは日本語システムフォントを基本に、外部フォント通信を必須にしない。

必要部品：PrimaryButton、SecondaryButton、IconButton、EggCard、TargetSegment、HeatSelector、LidToggle、CookingStatus、ScoreBreakdown、ShareActions、RankRow、SponsorCard、Toast、PauseDialog、EmptyState。

各部品は通常/押下/選択/フォーカス/無効/読込中を持つ。ランキングの空/通信失敗、PNG準備中、共有キャンセルは別状態にする。

UI_DESIGN.htmlは画面設計を確認するためのHTMLです。ゲーム機能や外部送信は実装していません。調理画面に置いたhero.pngは合成見本であり、本番では動く3Dへ置き換えます。

デザイン見本の96点、名前、順位、PR枠はサンプル表示です。最終結果の食品状態・採点内容・公開ランキングは実データから表示してください。
