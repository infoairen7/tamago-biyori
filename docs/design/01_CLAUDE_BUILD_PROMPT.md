# Claude用・制作開始プロンプト

以下を制作指示として実行してください。

あなたはブラウザ3Dゲームのエンジニア兼UI実装者です。添付資料を使い、日本語ゲーム「たまご日和」を実装してください。タイトルは仮称です。企画の説明だけで終わらず、起動できるソースコードとREADMEを作ってください。

## 1. 目的と完成像

プレイヤーが料理人の主観視点で、小さな目玉焼き専用フライパンに卵を割り、火加減とふたを調整して仕上げます。出来栄えを0〜100点で採点し、出来た目玉焼きの画像と結果をXで共有でき、オンラインの週間ランキングに参加できます。おいしそうな見た目・焼ける音・再挑戦の気軽さから「目玉焼きを食べたい」につなげ、結果画面に卵企業の商品紹介を自然に置きます。

1回の調理は目安30〜60秒、調理上限90秒。選択や結果閲覧の時間は含みません。実際の調理温度・時間の指南には使わない、短縮したゲーム表現です。

## 2. 入力資料の優先度

1. 本指示書と02_GAME_UX_SPEC.mdのゲームルール。
2. 03_ONLINE_AND_BRAND.mdのオンライン仕様。
3. game-config.json / design-tokens.json。
4. UI_DESIGN.htmlとPNG画面見本の見た目。

画像見本の数値や人物名はサンプルです。サンプルのランキングを公開ランキングとして表示しないでください。資料間に矛盾があれば数値設定とゲームルールを確認して実装判断を明記してください。

## 3. 技術構成

- 原則TypeScript、Vite、React、Three.jsのWebGLRenderer。インストール時の安定版を確認して互換性のある組み合わせを固定し、lockfileを含める。
- UIはHTML/CSS。ゲーム内の日本語を3Dテクスチャに焼き込まない。
- 描画非依存のGameModelに状態遷移・熱・焼き加減・採点を置く。3DとCanvas 2Dは同じモデルを読む。
- WebGL 2の利用可否を検出し、初期化失敗・重大な描画失敗では軽量2Dへ。コンテキストを失った瞬間にシミュレーションを止め、同じ状態から再開する。
- WebGPU、専用アプリ、VR、ポインターロックを必須にしない。
- スマートフォン縦持ちが基準。横持ち、タブレット、PCにも対応。向きの固定や全画面許可を必須にしない。
- 音は開始ボタンなどユーザー操作後に有効化する。初期設定は控えめ。音なしでも遊べる。
- サーバーがない環境では遊べるローカル版を作る。オンライン機能はインターフェースを分離し、未接続を明示する。

## 4. 必須画面

タイトル / 卵・焼き加減選択 / 卵を割る / 調理 / 結果 / ランキング / 設定・遊び方。ランキング登録、商品詳細、共有はダイアログまたはシートでよい。

画面の文章、操作領域、空状態、失敗時の振る舞いは仕様書を参照。390×844を基準に、320px幅でも横スクロールなし。主要ボタン48px以上、最終「お皿にうつす」は56px以上。safe-area、100dvh、文字拡大に対応する。

## 5. 調理体験

- 固定した主観視点でフライパンを見下ろす。歩行や視点移動はなし。パンはプレイ領域の55〜70%を使い、黄身と白身を大きく見せる。
- 卵は白い卵・赤い卵・うずら卵の3種類。白と赤で品質・栄養・点数優遇を捏造しない。初期性能は同じ。うずらは小さく、ゲーム上の進行だけ少し速い。
- 開始前に「とろり / ほどよく / しっかり」の目標を選ぶ。どれも満点を狙える。
- 卵を1回タップでひび、もう1回で割る。Enter/Spaceでも操作可。殻が開き白身と黄身がパンへ落ちる短いアニメーション。入力連打で卵を重複生成しない。割り方の点数・失敗は設けず、焼き加減に集中させる。
- 卵が落ちた時点で調理開始。中火が初期値。火力は「切 / 弱 / 中 / 強」の4つの大きなボタン。
- ふたは開閉トグル。蒸し焼きで黄身の進行が速くなる。透明ガラス、または補助ラベルで状態を把握できる。
- 火を切っても余熱は残る。「お皿にうつす」で採点を確定し、それ以降のアニメーション中は値を変えない。
- 白身の透明→白、縁の黄金色→焦げ、黄身のつや→マットへの変化、微細な泡、湯気をモデル値に連動させる。実際の結果画像も同じ状態から作る。
- ゲームモデルは固定ステップ1/60秒。端末FPSで採点結果を変えない。乱数を使う形状はrun seedで固定。
- バックグラウンド移行で一時停止。復帰後に再開ボタンを押すまで熱を進めない。長時間の差分をまとめて加算しない。

## 6. 採点・ランキング

02_GAME_UX_SPEC.mdの式を実装。白身40点＋黄身40点＋焼き色20点。生の白身と強い焦げには総点上限を適用。卵を割る速さ、課金、広告閲覧、端末性能は採点対象にしない。

全種類・全目標で90点以上を取れることをシミュレーションで確認する。設定調整はconfigだけで行う。採点バージョンを必ず記録する。

オンラインではサーバー発行のrunIdと操作ログを送り、サーバー側の同一モデルで再計算する。クライアントのscore値をランキングに直接保存しない。実装するDB、API、入力検証、重複送信対策を明示する。異常なログや期限切れは拒否し、ローカルの遊びは維持する。

ランキングは卵種×目標×採点バージョン×週で分け、同条件で比較。各参加者は同区分で自己ベスト1件。サーバー未接続のときは「ランキングに接続できません」を表示し、架空の参加者で埋めない。

## 7. X共有と企業PR

- 「Xにポスト」：結果テキスト＋公開URL＋ハッシュタグをWeb Intentで開く。URLSearchParamsで正しくエンコードし、投稿はユーザーが確定する。
- 結果画像を1200×630 PNGで生成し、プレビュー・保存ボタンを用意する。ユーザー自身の結果の目玉焼きを大きく載せる。
- Web Share APIでファイルを共有できる環境のみ「画像を共有」を表示。Xが共有先に現れることや画像・文言が同時に引き継がれることを保証しない。
- Web Intentにローカル画像を自動添付できると実装しない。画像保存→Xで添付する案内を用意する。
- 未公開時は存在しないURLを投稿文に入れない。画像生成や共有のキャンセルでゲーム結果を失わない。
- 協賛企業の設定はsponsor-config.example.jsonを基に差し替える。調理中に広告モーダルを出さない。結果画面に「今度は、本物のたまごで。」の自然な導線と「PR」表示を入れる。
- 商品データが未設定のときはPR枠を非表示。実在の商品特徴、受賞歴、効能、購入先を創作しない。

## 8. 素材

assets/hero.pngはタイトル用・質感参考です。完成イラストを調理中ずっと貼り付けて3D実装の代わりにしないでください。

卵PNGは選択カード用。3Dのフライパン・卵・殻・ふた・皿・キッチンはプロシージャル形状で実装できること。外部GLBや音源なしでも起動可能にする。04_ASSET_GUIDE.mdにモデルと音の制作指示があります。画像ファイルが渡されていない場合は欠落を伝え、コードで仮表示を作り、差し替えパスを残してください。

## 9. 実装順序と完了条件

### 段階1：ローカルで遊べる完成形

タイトル→卵選択→割る→調理→採点→再挑戦を完成させる。設定、ローカル自己ベスト、3D/2D、音量・一時停止を含める。画面だけで終了しない。ランダムに点数を付けない。

### 段階2：シェアとPR

プレイ結果から画像生成、X投稿画面、画像保存、対応端末で画像共有、協賛企業設定による表示切り替え。失敗時のUIを含める。

### 段階3：公開ランキング

永続DBとサーバーAPI、匿名プレイヤー識別、操作ログ再計算、入力検証、週区切り、公開登録、取得、自己ベスト更新。未接続時のローカルモードを残す。接続先が無ければバックエンドのコード・スキーマ・設定手順まで出し、未稼働の機能を稼働済みと言わない。

### 段階4：調整と実機確認

320pxスマホ、iOS Safari、Android Chrome、PC Chrome/Edge/Firefox/Safariを対象に、利用できる範囲で確認。実機未確認は区別して報告する。iOSの音、ページ復帰、縦横切り替え、3D不能時の2D、共有未対応、オフライン、二重送信、低FPSで同スコアを重点確認する。

## 10. 成果物と確認

- ファイル構成、インストール・起動・ビルド手順、環境変数例、オンライン設定手順。
- プロダクションビルドが成功し、主要遷移で例外がないこと。
- 同じ操作ログは30/60/120fpsの描画でも同じ点数。0〜100点から逸脱しない。生・焦げの上限、時間上限、停止後の不変をテスト。
- ランキングの任意スコア送信、run再利用、異常step、別ユーザーのrun送信が拒否されること。
- 操作できないダミーボタンや未接続の処理は明示する。
- 認証情報をフロントコードへ埋め込まない。

まず現在の作業環境でできる範囲を短く示し、段階1の実装から着手してください。小さな実装判断は自分で行い、不要な質問で止まらないでください。

# 途中で追加する短い指示

## 見た目が弱い場合

> 機能を維持して、添付UIの余白・タイポグラフィ・クリーム色と深緑・大きな黄身の見せ方へ近づけてください。3Dは白身の不透明化、黄身のつや、縁の焼き色、湯気、パンの接地影を優先してください。モバイル30fpsを保ち、静止画でゲームを代用しないでください。

## オンライン実装に進む場合

> 03_ONLINE_AND_BRAND.mdに従い、ランキングのサーバー検証と永続化を実装してください。データベースや公開先の設定が必要なら、コード・スキーマ・環境変数例を先に完成させ、接続のために必要な情報だけまとめて提示してください。秘密鍵はサーバーだけで使用します。

## 公開前の確認

> 受け入れ条件を一覧にして検証してください。実行済みの確認、コードだけで確認した項目、実機未確認を分けてください。結果画像が実際の焼き加減と一致し、ランキングに偽の点数を直接登録できず、通信がなくてもローカルで遊べることを重点確認してください。
