# たまご日和（仮タイトル）

じゅわっ、とろっ。今日のひと皿。

料理人の主観視点で、小さなフライパンに卵を割り、火かげんとふたで理想の目玉焼きをつくるブラウザゲームです。スマートフォン縦持ちを基準に、横持ち・タブレット・PCでも遊べます。

- 卵3種（白い卵・赤い卵・うずら卵）× 黄身3種（とろり・ほどよく・しっかり）× 縁の焼き目3種（しろく・ほんのり・カリッと）。どれでも100点を目指せます
- 焼くたびに「こだわり」が増えます：油の量 → 差し水（調理中に1回、ふたと合わせて蒸し焼き）→ 油の種類（サラダ油・バター・ごま油）。詳しくは [`docs/GAME_DEPTH_V2.md`](docs/GAME_DEPTH_V2.md)
- 3D（Three.js / WebGL 2）で描画し、使えない環境では同じゲームモデルを読む軽量2D表示に切り替え
- 結果画像（1200×630 PNG）の保存・共有、Xの投稿画面、協賛企業のPR枠（設定時のみ）
- 公開ランキング（任意）：サーバーが操作ログから点数を再計算。クライアントの点数は受け取りません

> このゲームの加熱モデルはゲーム用の簡易モデルです。実際の調理時間・温度・安全性の目安ではありません。

**遊ぶ：https://infoairen7.github.io/tamago-biyori/** （GitHub Pages。ランキングは未接続のローカル版）

制作資料（仕様書・画面デザイン）は [`docs/design/`](docs/design/) にあります。検証結果は [`docs/VERIFICATION.md`](docs/VERIFICATION.md) を参照してください。

## 必要なもの

- Node.js **22.18 以上**（サーバーとテストは Node の TypeScript 実行機能と標準の SQLite を使うため）
- 追加のデータベースや外部サービスは不要です

## すぐに遊ぶ（ローカル版）

```bash
npm install
npm run dev          # http://localhost:5173 を開く
```

ランキングの接続先を設定していない状態では、ランキング画面は「ランキングに接続できません（このサイトでは未設定）」と表示し、架空の参加者は出しません。調理・採点・自己ベスト・画像保存・X投稿画面はすべて動きます。

## ランキング込みで動かす

```bash
# ターミナル1：ランキングサーバー（http://localhost:8787、SQLiteは data/ に作成）
npm run server

# ターミナル2：フロントエンド（/api はサーバーへ中継されます）
VITE_API_BASE=/ npm run dev
```

本番（1つのNodeプロセスで画面とAPIを同じオリジンから配信）:

```bash
VITE_API_BASE=/ npm run build
npm start            # dist を配信しつつ /api を提供（PORT=8787）
```

Docker でも同じ構成で起動できます（`Dockerfile`。データは `/app/data` ボリュームに保存）。

## 公開（GitHub Pages）

`.github/workflows/pages.yml` が main への push ごとに GitHub Pages へ公開します。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を「GitHub Actions」にする
2. （任意）ランキングサーバーを別の場所で動かす場合は、**Settings → Secrets and variables → Actions → Variables** に `VITE_API_BASE`（例：`https://api.example.com`）を登録し、サーバー側の `ALLOWED_ORIGINS` に Pages のオリジン（例：`https://<ユーザー名>.github.io`）を設定

Pages は静的ホスティングなので、Pages だけで公開した場合はランキングは「未接続」表示のローカル版になります。Xの投稿文には Pages の公開URLが自動で入ります。

`.github/workflows/ci.yml` は push / PR ごとに型チェック・テスト・シミュレーション・本番ビルドを実行します。`package-lock.json` が無い場合は初回に生成してコミットします。

## 設定の差し替え

| ファイル | 内容 |
|---|---|
| `config/game-config.json` | 卵・目標・熱と焼き加減の係数・採点。**採点を変えたら `scoringVersion` を上げる**（ランキングはバージョンごとに分かれます） |
| `config/design-tokens.json` | 色・文字・余白（`src/styles.css` の変数と結果画像で使用） |
| `public/config/sponsor.json` | 協賛企業の設定（`config/sponsor-config.example.json` と同じ形）。`enabled:false`・社名なし・購入先URLなし・キャンペーン期間外ではPR枠を表示しません。ビルドし直さずに差し替え可能 |
| `public/assets/*.webp` | タイトル画像・卵カード画像（元画像は `assets/original/`） |
| `src/game/audio.ts` の `SOUND_FILES` | 効果音ファイルへの差し替え（`public/audio/` に置いてパスを書く）。未設定なら Web Audio の合成音 |

環境変数は `.env.example` を参照してください。フロントエンドの `VITE_*` はビルドに埋め込まれるため、秘密の値は入れないでください（管理用トークンなどはサーバー側の環境変数だけに置きます）。

## ゲームの仕組み

- `shared/model.ts` が仕様書の式（T/W/Y/B/D、白身40＋黄身40＋焼き色20、生の白身は39点・強い焦げは49点の上限）を土台に、採点バージョン2.0.0で油・差し水（蒸気S）・縁の焼き目の目標を加えています。はじめの1皿（サラダ油・ふつう・差し水なし・縁ほんのり）は仕様書と同じ計算です（[`docs/GAME_DEPTH_V2.md`](docs/GAME_DEPTH_V2.md)）
- 描画は毎フレーム、実時間を固定ステップ（1/60秒）に変換してモデルを進めます。1フレームで取り込む時間は最大0.25秒で、長い停止の差分はまとめて加算しません
- 操作は「何ステップ目に何をしたか」の整数ログで記録します。同じログは30/60/120fpsのどの描画でも同じ点数になります（テスト済み）
- タブの非表示・一時停止・WebGLコンテキストの喪失では熱も時間も止まり、「続ける」を押すまで進みません
- 結果の皿の画像・共有画像は、採点が確定した瞬間の W/Y/B/D と seed から描き直したものです（UIのスクリーンショットではありません）

## ランキングの仕組みと不正対策

| API | 役割 |
|---|---|
| `POST /api/session` | 匿名プレイヤーのトークンを発行（サーバーにはハッシュのみ保存） |
| `POST /api/runs` | 卵・黄身・縁・油・油の量を受け取り、runId・seed・採点バージョン・有効期限（15分）を発行 |
| `POST /api/runs/:id/finish` | 操作ログと終了stepを受け取り、サーバーの同じモデルで再計算して結果を確定 |
| `POST /api/results/:id/publish` | 表示名を付けて公開登録（任意・1回だけ） |
| `GET /api/leaderboard` | 卵×黄身×縁×採点バージョン×期間（週間/全期間）の上位50件と自分の記録。各行に使った油・差し水の秒も表示 |
| `POST /api/admin/results/:id/hide` | 運営用：不適切な名前の記録を非表示（`ADMIN_TOKEN` 設定時のみ） |

- クライアントの点数は受け取りません（`score` を含む送信は明示的に拒否）
- seq連番・step 0〜5400の整数・非減少・操作の許可リスト（heat/lid/water、差し水は1回まで）・重複除去後500件以内・終了stepの範囲・実経過時間との整合を検証します。油や縁はrun発行時の値で再計算します
- 同じrunの再送は同じ結果を返し、異なるログへの差し替えは拒否します。状態を条件にした更新と runId の一意制約で二重登録を防ぎます
- 別のプレイヤーの run の終了・公開はできません。期限切れの run は拒否し、結果は端末内の記録として残ります
- 週は日本時間の月曜00:00区切り（DBはUTCのミリ秒）。同点は同順位（1,1,3）、各参加者は区分内の自己ベスト1件
- 認証はCookieではなく `Authorization: Bearer` のトークンなので、CSRFの対象になりません。CORSは `ALLOWED_ORIGINS` のオリジンだけ許可、送信サイズ上限64KB、IP単位の簡易レート制限あり
- 操作ログは `EVENTS_RETENTION_DAYS`（初期30日）で削除します

再計算は任意の点数の直送や不可能なログを防ぎますが、正しく成立する操作ログの自動生成や複数アカウントまでは防げません。賞品付きのキャンペーンを行う場合は、本人確認や監視などを別途設計してください。

## 実装で判断したこと

- **テスト**：Node 標準のテストランナーで、依存パッケージなしに実行できる形にしました
- **匿名識別**：Cookie ではなく端末に保存するトークン（別ドメインのAPIでもサードパーティCookie制限の影響を受けないため）
- **X投稿**：`window.open` ではなく通常のリンク（`target="_blank"`）で開きます。ポップアップブロックの影響を受けず、ゲーム画面も残ります
- **基礎点の表示**：3項目の表示値は最大剰余法で整数に配分し、合計が基礎点の丸め値と必ず一致するようにしています。焦げ減点・上限は別行で表示します
- **初回ヒント**：はじめての調理だけ「白身の透明感がなくなるまで待とう」「ふたをすると黄身が進みやすい」を表示（設定で切替可）。差し水が使えるようになってから2皿は、差す目安（白身が白くなりはじめた頃）も表示。正解時刻のカウントダウンは出しません
- **段階的な解放**：1皿目は設計1.0と同じシンプルさ。焼いた皿の数は端末に保存し、設定の「こだわりをすべて使えるようにする」で待たずに全部選べます。ランキングは解放状況に関係なく同じ条件で比べます
- **低速端末**：描画が4fpsを下回るような端末では、ゲーム内時間が実時間よりゆっくり進みます（点数の決まり方は変わりません）
- **ランキングのrun発行**：「この卵で焼く」を押したときに最大2.5秒だけ待ち、発行できなければその場で端末内の記録として開始します

## 既知の制限・未確認事項

- 実機（iOS Safari、Android Chrome、各PCブラウザ）での表示・音・FPSは未確認です。詳細は [`docs/VERIFICATION.md`](docs/VERIFICATION.md)
- 効果音は合成音の仮実装です。本番用の音源は `SOUND_FILES` から差し替えてください
- 協賛企業の名称・ロゴ・商品情報・購入先URL、公開URL、ランキングの運用担当は未設定です
- 結果ごとの公開ページや動的OGP画像は未実装（初期は共通のゲームURLと画像保存で成立させる方針）
- 計測（`src/game/analytics.ts`）は `window.dataLayer` とブラウザ内イベントへ流すだけで、外部サービスには送っていません
